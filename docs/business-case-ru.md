# Business case — обработка входящих обращений

**Проблема.** В малой компании письма и сообщения клиентов попадают в общую очередь. Сотрудник вручную читает сообщение, выясняет тему, определяет приоритет, выбирает ответственного и готовит следующий шаг.

**Решение.** Process Pilot автоматизирует первый этап: классифицирует обращения, выделяет потенциально срочные, маскирует распространённые контактные данные, предлагает команду и черновик следующего действия. Опциональная LLM может улучшить текст предложения, но не может самостоятельно сменить приоритет.

**Что показывает демонстрация.** Веб-приложение с историей обращений, API, отчётом по категориям, оценкой предполагаемой трудоёмкости, локальным режимом и MCP-инструментами для coding agents.

**Метрика пилота.** До внедрения измерить среднее время ручной классификации 30–50 типовых запросов; после внедрения — время проверки предложений системы плюс стоимость настройки и ошибок.

## Пример оценки (вымышленный)

| Допущение | Значение |
| --- | ---: |
| Обращений в месяц | 2 000 |
| Предполагаемое уменьшение ручной работы | 4 мин / обращение |
| Стоимость рабочего часа | 900 ₽ |
| Условный высвобожденный ресурс | 133,3 ч |
| Его условная стоимость | 120 000 ₽ / месяц |

Внимание: **120 000 ₽ — не экономия, достигнутая проектом**. Нужно вычесть затраты на внедрение, проверки, LLM API, хостинг, ошибки и эксплуатацию. Измерение и валидация гипотезы — обязательные этапы.
