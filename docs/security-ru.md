# Безопасность и границы применения

## Что проект уже делает

- По умолчанию не использует внешние LLM API и не требует ключей.
- Маскирует типовые email-адреса и российские телефонные номера **до** записи в SQLite.
- Удалённые запросы возможны только при явном режиме `remote`, заданном серверным администратором, и явном `use_llm=true` для конкретного вызова.
- Не хранит секреты в коде. Используйте переменные окружения; `.env` исключён из Git.
- Не использует пользовательский текст как доверенный HTML: frontend экранирует вывод.
- MCP-инструменты работают на просмотр и предварительную классификацию, без удалённого управления системой.
- HTTP dashboard проверяет разрешённые `Host`-имена и блокирует browser cross-origin mutations.
- Security middleware использует raw ASGI path для security-решений и не полагается на реконструированный URL.
- Для dashboard/API выставляются базовые security headers; API-ответы помечаются `Cache-Control: no-store`.

## Host allowlist

По умолчанию ожидаются локальные имена: `localhost`, `127.0.0.1`, `::1`, а также service-name `processpilot` для контейнера. Для тестов разрешён `testserver`.

При осознанном размещении за reverse proxy добавьте домен:

```bash
PILOT_ALLOWED_HOSTS=pilot.example.com
```

Несколько значений разделяются запятыми. `*` отключает Host-защиту и для публичного сервиса не рекомендуется.

## Чего проект НЕ гарантирует

- Regex не удаляет имена, адреса проживания, паспортные данные и другие типы персональных сведений.
- База SQLite хранится без шифрования и локального разграничения пользователей.
- Нет аутентификации, управления ролями, rate limiting, полноценного audit log или consent workflow.
- Нет полного app-level лимита тела chunked-запросов; для reachable/public deployment нужен reverse proxy с request-size limits.
- Не проводилась независимая оценка кибербезопасности и соблюдения российского законодательства.
- Режим `remote` может передавать маскированную часть данных стороннему AI-поставщику. Перед включением проверьте условия обработки и договорные требования.

## Правила использования

1. Держите демо на localhost, Docker Compose слушает только `127.0.0.1:8000`.
2. Не вставляйте реальные данные клиентов в публичные демо или тестовые репозитории.
3. Не открывайте port 8000 напрямую в интернет. Для production нужны аутентификация, авторизация, HTTPS/reverse proxy, rate limiting, request-size limits, логирование и threat model.
4. Для внешней модели применяйте только согласованного поставщика. Установите лимиты на расходы и ограничьте сетевой выход.
5. Для production настройте хранение, сроки удаления, резервное копирование и политику доступов.
6. Секрет, случайно добавленный в Git, нужно ротировать; удаление из последнего коммита не удаляет его из истории.
7. При размещении на домене явно задайте `PILOT_ALLOWED_HOSTS` и не используйте `*` без осознанной причины.
