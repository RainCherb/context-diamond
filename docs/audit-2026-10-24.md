## Исправленные проблемы

### 1. Утечка SQLite-соединений — исправлено

**Проблема:** `sqlite3.Connection` использовался через `with connection`, но такой контекстный менеджер управляет commit/rollback и не закрывает соединение. На долгоживущем процессе соединения оставались открытыми до сборки мусора.

**Исправление:** добавлен единый `Store.connection()` с `try/finally` и обязательным `close()`. Тесты запускаются с `ResourceWarning` как с ошибкой.

### 2. 500 на строках из пробелов — исправлено

**Проблема:** строка из 5+ пробелов проходила `min_length`, затем `classify()` выбрасывал `ValueError`; API вместо ошибки пользователя мог завершить запрос исключением.

**Исправление:** текст и источник нормализуются до Pydantic-ограничений; whitespace-only и слишком короткий текст возвращают **422**.

### 3. `NaN` / `Infinity` ломали ответ ROI API — исправлено

**Проблема:** нестандартные JSON-числа могли попасть в validation error. Стандартный JSON encoder затем не мог сериализовать `nan/inf`, что превращало ожидаемый 422 в 500.

**Исправление:** ROI запрещает non-finite числа, а отдельный безопасный validation handler санитизирует детали ошибок перед JSON-ответом.

### 4. Non-finite значения из environment — исправлено

**Проблема:** `PILOT_LLM_TIMEOUT_SECONDS=nan` или тариф `inf` мог попасть в runtime и привести к некорректному timeout/стоимости.

**Исправление:** environment float parser принимает только конечные числа, применяет нижнюю границу и возвращает безопасный default при ошибке.

### 5. Конкурентная двойная загрузка demo — исправлено

**Проблема:** два одновременных `POST /api/demo/seed` могли оба увидеть пустую БД и вставить одинаковый набор.

**Исправление:** `BEGIN IMMEDIATE` + атомарный `seed_if_empty()`. Добавлен конкурентный regression test.

### 6. Ложное удвоение `счет` / `счёт` — исправлено

**Проблема:** после нормализации `ё→е` оба правила превращались в один сигнал, но считались дважды и могли менять победителя категории.

**Исправление:** нормализованные шаблоны дедуплицируются до подсчёта.

### 7. Ложные keyword-срабатывания — исправлено

Примеры старого поведения:

- `несрочно` содержало `срочно` и могло давать высокий приоритет;
- `посуда` содержала `суд` и могла выглядеть как legal escalation;
- английские `border`, `industrial` содержали `order` / `trial` и могли ошибочно попадать в delivery/sales.

**Исправление:** для risk-термов используются границы начала слова; для английских категорий — полные word boundaries. Rules-based движок всё равно остаётся эвристикой и не является семантическим классификатором.

### 8. Host / DNS-rebinding поверхность — усилено

**Проблема:** локальный HTTP-сервис без проверки `Host` может быть атакован через browser DNS rebinding. Дополнительно нельзя строить security-решения на реконструированном `request.url.path`.

**Исправление:** добавлен configurable Host allowlist (`PILOT_ALLOWED_HOSTS`), malformed Host отклоняется, а security middleware использует raw ASGI `scope["path"]`. State-changing browser requests с чужим `Origin` блокируются.

### 9. Security headers — добавлено

Добавлены `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`, `Cache-Control: no-store` для API и CSP для dashboard.

### 10. LLM URL и response validation — усилено

- URL с query/credentials/fragment/некорректным port отклоняется;
- cloud metadata/link-local адреса блокируются;
- redirect и proxy inheritance отключены;
- action очищается от внешних пробелов и не может пройти как строка из пробелов;
- deterministic category/priority остаются неизменными — LLM меняет только предложенное действие.

### 11. MCP input bounds — исправлено

`preview_ticket` теперь использует те же границы текста (5–8000 символов), что и HTTP API, чтобы агент не мог случайно передать неограниченный контекст.

### 12. Responsive navigation 761–1100 px — исправлено

Старая CSS-логика скрывала все неактивные пункты sidebar в компактном режиме. Теперь все navigation icons остаются доступны.

### 13. Remote-mode UI мог вводить в заблуждение — исправлено

Sidebar всегда говорил «Локальный режим», даже при разрешённом external LLM. Теперь статус меняется по `/api/config` и прямо предупреждает, что маскированный текст может отправляться внешнему API.

### 14. ROI race в браузере — исправлено

Несколько быстрых изменений input могли вернуть HTTP-ответы не по порядку и показать устаревшее значение. Добавлена revision guard: UI применяет только последний расчёт.

### 15. Защитное экранирование frontend — усилено

Дополнительные server-derived поля (`status`, id/reasons fallbacks) теперь обрабатываются безопаснее перед вставкой через `innerHTML`.

## Зависимости и CI

- Минимальная версия FastAPI поднята до современного диапазона.
- Явно требуется `starlette>=1.3,<2`, чтобы не разрешать установку старых веток с известными Host/URL parsing проблемами.
- CI запускает Python 3.11, 3.12, 3.13.
- Ruff теперь запускается по конфигурации проекта (`ruff check src tests`).
- CI дополнительно собирает wheel и проверяет, что frontend assets попали в пакет.

## Что сознательно остаётся ограничением MVP

Эти пункты не являются «починенными production-функциями», потому что проект позиционируется как локальный портфолио-пилот:

- нет корпоративной аутентификации и RBAC;
- нет multi-tenant isolation;
- нет rate limiting и полноценного request-body limiter;
- SQLite не зашифрована at rest;
- маскирование PII покрывает только типовые email и российские телефоны;
- нет retention/delete workflow;
- нет production queue/retry для LLM;
- нет готового Telegram/CRM webhook-коннектора;
- rules-based классификация может ошибаться на отрицаниях и сложной семантике;
- перед реальным публичным размещением нужен reverse proxy, HTTPS, authentication, observability, backups и отдельный threat model.
